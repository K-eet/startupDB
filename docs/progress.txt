- Org accounts + hybrid event posting + admin moderation (2026-07-04)
  - Auth model: ONE account type (Google sign-in). "Organization" is a role (owner/member)
    a user holds on a company — no separate org login.
  - Hybrid event posting: org-affiliated users post instantly (status 'live'); unaffiliated
    users' posts enter a moderation queue ('pending_review'). Status is decided SERVER-side
    from the caller's memberships — a client-supplied status is ignored. "Post as" a company
    requires an approved membership on that slug (enforced server-side).
  - Org membership via claim/join (reuses the companyRequests pipeline): claim on an unowned
    company -> admin approves -> submitter becomes 'owner'; join on an already-owned company
    -> an owner approves (admin fallback) -> 'member'. requestKind is derived at APPROVAL time
    from the target's ownerUids (avoids a submit-time TOCTOU).
  - Data model: new users/{uid} (memberships[] + memberSlugs[] flat mirror for the
    array-contains roster query); companies gained ownerUids[], plus published + userSubmitted
    on user-added entries; companyRequests gained uid + requestKind; new events collection
    (StoredEvent: title/date/time/location/online/category/tags/status/ownerUid/postedByName/
    companySlug?/companyName?/createdAt).
  - All writes via Admin SDK server routes — NO firestore.rules or firestore.indexes changes
    (respects CLAUDE.md #2/#7). Single-field auto-indexes only; status/ownerUid filtered in
    memory to avoid composite indexes.
  - ownerUids <-> users.memberships kept in sync inside ONE Firestore transaction (admin
    tx.get(query) resolves the company by its Slug field); the last-owner guard runs inside
    the same tx so a company can't be left ownerless (LastOwnerError -> 409).
  - New-company ("add") approval creates a HIDDEN draft (published:false) + grants the
    submitter ownership; admin enriches via the edit form then Publishes. Unpublished drafts
